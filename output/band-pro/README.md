# `band-pro/` — 16px · 64 色 · 原画质档

**不降分辨率**，只做减色 + 重打包 + 索引化。适合**屏幕更宽的手环**（手环 8 Pro / 9 Pro = 336 物理像素宽），或对画质有极端要求时。

## 参数（来自 `report.json`）

| 项 | 值 |
|---|---|
| tile 边长 | **16 px**（与原图同） |
| 调色板 | **64 色 / sheet** |
| 重采样 | box + alpha 预乘（同原 tile 大小，仅过 alpha 二值化） |
| 源 PNG 总体积 | 465.4 KB |
| **本档总体积** | **96.3 KB** |
| **压缩比** | **4.8×** |
| 解码后 RGBA 显存 | ≈ 2037 KB |

## 在手环上能看多远

| 屏幕 | 一屏 tile 数 |
|---|---|
| 手环 8 Pro / 9 Pro（336 物理像素宽） | **21 列 × 30 行**（与桌面视觉接近） |
| 手环 9（192 物理像素宽） | 12 列 × 30 行（同原版观感） |

## 何时选它

- 设备分辨率足够，不想损失任何细节
- 美术风格是「16px 像素画」，放大显示反而失真，保持原 tile 尺寸最清晰
- 显存不是瓶颈（2037 KB 在低端嵌入式上偏紧，但 RAM ≥ 几 MB 时没问题）

否则 `band/` 是更通用的选择。

## 体积拆解的真相

可能让你意外：本档相比源素材**只省了 79%**——但**没有任何画质损失**。剩余的 79% 都来自：

- 空 tile 剔除（角色动画里很多"等待帧"是纯透明的）
- 重复帧去重（同一动作的多帧像素完全相同）
- PNG-32 → PNG-8 + 索引色 + tRNS 二值透明

也就是说，**76% 的体积收益跟分辨率无关**，是图集本身的"浪费"。如果你做的是全新的游戏美术，这 76% 直接抄作业就够省下来了。

## 用法

```bash
python3 ../../tools/convert_sprites.py --preset band-pro

```
